   193→## 2. API Client Optimization
   194→
   195→### Issues Found
   196→- ❌ No request deduplication — multiple components requesting same endpoint fire N requests
   197→- ❌ No client-side response caching — every call hits the network
   198→- ❌ No cache invalidation after mutations — stale data served until page refresh
   199→- ✅ Timeout (30s) with AbortController already implemented
   200→- ✅ Offline queue for mutating requests already implemented
   201→
   202→### Changes Made (`src/lib/api-client.ts`)
   203→1. **Added inflight request deduplication for GET requests**
   204→   - `_inflightRequests` Map tracks in-flight GET requests
   205→   - If 3 components call `api.getProducts()` simultaneously, only 1 fetch is made
   206→   - All 3 callers receive the same Promise
   207→
   208→2. **Added short-lived client-side response cache (5s TTL)**
   209→   - `_responseCache` Map stores successful GET responses
   210→   - Prevents rapid re-fetches when components mount/unmount quickly
   211→   - Automatically expires after 5 seconds
   212→
   213→3. **Added cache invalidation after mutations**
   214→   - `invalidateCache(prefix)` method clears both internal cache and shared client-cache
   215→   - Applied to: `createProduct`, `updateProduct`, `deleteProduct` → invalidates products, inventory, dashboard
   216→   - Applied to: `createCustomer`, `updateCustomer`, `deleteCustomer` → invalidates customers
   217→   - Applied to: `createSale` → invalidates sales, dashboard, inventory, products, debts
   218→
   219→4. **Maintained all existing functionality**
   220→   - Offline queue, error handling, auth auto-logout, timeout behavior preserved

   238→## 4. Dashboard API Route Optimization
   239→
   240→### Redundant Query Fix (`src/app/api/dashboard/route.ts`)
   241→- **Before:** `totalStockValue` used `db.product.aggregate().then(() => db.product.findMany())` — the aggregate was completely wasted because SQLite can't multiply columns in aggregate, so findMany was always needed
   242→- **After:** Direct `db.product.findMany()` with `select: { quantity, costPrice, sellingPrice }` — eliminates 1 unnecessary DB query per dashboard load
   243→
   244→### Already Optimized (verified)
   245→- ✅ All independent queries run in `Promise.all()` (batched)
   246→- ✅ N+1 fix: topProducts uses batch `findMany({ id: { in: [...] } })` instead of per-product `findUnique()`
   247→- ✅ COGS uses single `findMany` instead of `aggregate + findMany`
   248→- ✅ Server-side SWR cache with 15s TTL + 30s stale-while-revalidate
